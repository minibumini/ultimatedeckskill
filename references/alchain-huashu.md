## 1. 让页面承担教学任务

从受众的业务问题组织课程：遇到什么问题 → 用什么方法理解 → 在行业案例里如何判断 → 怎样操作或练习 → 怎样知道做对了 → 回到工作后做什么。

逐页先写明学员应理解的一个判断或应完成的一项动作，再决定文字、图解和案例。每张图解释关系、步骤或决策，减少与知识无关的装饰。

页面类型按用途变化：封面建立课程与客户的关系；章节页给下一段任务；方法页解释结构；案例页展示触发情境和前后变化；实操页呈现步骤与结果；练习页要求应用；结尾页留下可执行的动作或检查清单。

信息密度随页面任务起伏。封面与转场可以稀疏，方法、对比、练习和真实截图页可以更密。尽量让观众快速识别主旨，解释细节由讲师备注、讲义或下一页承接，不为了凑模板把每页都做成三栏。

**保留用户封面规范**：左上客户真实 Logo；背景为该客户的工程、重点项目、产品或业务现场；正式标题使用高亮金色、飘逸凌厉的中文手写体；底部姓名与培训日期。正式长标题可合理换行，不为迎合外部 Skill 的字数上限擅自改名。

## 2. 用中文提示词表达具体设计

一条页面提示词包含：统一视觉规范的短版、本页准确文案、真实行业场景、需要解释的关系，以及必要参考图的用途。尽量使用中文，保留真实品牌名和必要技术标识。

风格参照选择与行业和课堂目的有关的真实视觉锚点：客户已有材料、真实产品图、已核验项目照片、统一样页，或合适的设计语言。解释具体结构比堆“高级感”“专业感”更有效，不机械凑两个设计师或品牌名称。

传入多张参考图时说明每张的范围，例如“图 1 只继承客户 Logo，图 2 只参考工地环境，图 3 只延续颜色和字体气质”。不要继承参考页的旧文字、数据、编号或无关人物。

将需要显示的中文逐字列清；未核的产品参数、项目成绩和客户案例不让模型自由补全。视觉参考中的出版物或品牌名称只用于理解样式，生成后检查是否误画成外部标识、英文页眉或水印。

出现缺陷时先定位最影响使用的一项：错字、字号过小、图解关系错误、Logo变形、行业物件错误或风格漂移。一次修改以一个主要问题为目标；相互依赖的问题一起修复。保留已通过的内容与视觉规范，再调用生图重新检查，避免无变化地重复生成。

## 3. 让课件支持讲课与实操

- **开场**：告诉学员培训后能完成什么具体任务，结合本行业的真实困难，不保证收入、效率或业务成果。
- **提问**：围绕有经验可判断、有方法可回答的问题设计互动；讲师备注留出思考时间。实操环节可以使用电脑和手机。
- **回扣**：重要概念通过行业案例、实际操作和小练习再次出现，不机械把同一句话重复三遍。
- **转场**：说清已完成的任务和接下来要解决的问题，让走神的学员重新跟上。
- **结尾**：留下下一步行动、可复用方法或自查清单，问答期间仍可展示。避免用空泛感谢页替代实用内容。

讲师的完整解说、提问时机和演示操作放备注或讲义；页面保留学员当下需要看懂的内容。

## 4. 保留统一视觉与真实验收

同一课件沿用统一亮/暗基调、少量强调色、字体气质、图形语言与行业物件；构图变化服务不同教学任务。通过真实客户资产和统一样页维持识别。

参考五个观察维度：是否延续视觉规范、信息层级是否清楚、细节是否一致、图像是否帮助理解、是否有可记住的核心表达。另查行业真实性、数据依据、中文准确、Logo保真、投影阅读、图像比例和最终页数。

**所有封面与内页直接生图**：使用当前会话实际可调用的 ImageGen，或环境确有的 Images 2.5。不能以 HTML、SVG、Canvas 绘制后截图冒充生图。生图失败先定位和修复，存在真实阻塞时如实说明，不能自动改走 HTML。

字号沿用本 Skill 主规范：**正文 28 号、标题 40 号为优先目标**；信息密集页可以适度放宽，以实际投影可读、层级清楚、内容不挤为准。图片中的字号要通过画面尺度和投影阅读核验，不能仅因提示词写了数值就声称全部合格。

当前会话优先直接调用 ImageGen 工具。不通过 `huashu-gpt-image/scripts/gen_via_codex.py` 再次启动 Codex 并按共享目录“最新文件”取图；文件存在不能证明真正调用了模型。组装继续使用本 Skill 的图片存在性、比例与成品页数校验，另将清单逐项与大纲核对，发现漏列计划页；不采用缺图时跳过的脚本行为。

## 5. 不继承的外部规则

不叠加固定三个版本、逐阶段人工批准或每次都访谈的流程；确有关键取舍才询问，用户已确定的方向继续执行。

不默认注入作者花叔的像素头像、私有目录、个人品牌、推广水印或渠道资产；客户 Logo 与米尼身份按本任务素材使用。

不要求额外密钥、安装网页桥或扩展，不自动上传图床，也不因额度或工具失败自动转付费接口或其他账户会话。新费用和新权限按实际授权处理。

不采用演讲 Skill 的全文 ≥40 号、删除 Logo、只能一张复杂页或一律纯色背景规则。客户封面、行业环境和信息密集页保留本 Skill 已确认的弹性；生图故障也不触发 HTML 降级。

## 6. 女娲的使用边界

女娲用于用户**明确要求**时，从给定来源提炼某个主题的方法、心智模型、决策步骤和表达特点，帮助组织课程内容。安装本技能不触发人物蒸馏，不默认创建人物 Skill 或角色扮演。

方法借鉴不等于本人观点、参与授课或商业背书。课件不能暗示被提炼人物认可米尼、客户、课程或其中的业务结论；引用与推断要分清。

## 7. 其他来源的取舍

- `huashu-design`：HTML 原生设计与固定三方向门较重；已吸收其视觉判断和评审，不让 HTML 主线替换全页生图。
- `huashu-slides`：合集的较早 PPT 流程，默认可编辑 HTML，生成依赖外部 Gemini；本次吸收更贴合的 slide-codex 方法。
- `huashu-slide-doubao`：需要豆包内置生图环境，Codex 路线无需重复安装。
- `huashu-report`：研究报告与咨询报告方法，适合证据和图表参考，不引入完整报告流水线。
- `feynman-skill`：人物视角 Skill，可以参考理解检验与具体演示，不作为一般解释或课件制作的默认角色。
- `huashu-md-html`、`huashu-art-motion`、`huashu-icon-set`、`seedance-skill`：资料转换、动画、图标或视频能力按具体任务需要使用，不属于本技能依赖。
- `deepseek-v4-deep-dive`、`img2046`、`agent-skills-orange-book`：树核验未发现 SKILL.md，分别为案例、产品和电子书，不能当作 Skill 安装。
